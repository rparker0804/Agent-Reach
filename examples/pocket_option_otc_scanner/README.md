# Pocket Option OTC Scanner

This scanner watches Pocket Option OTC currency pairs in real time. It builds candles from the live quote stream and runs a configurable set of technical indicators on them. When a pair meets a rule you define (for example RSI extremes or MA/MACD crossovers), it flags the pair on the console, and optionally in a JSON-lines file.

```
2026-09-23 20:09:00 UTC EURUSD_otc   ▼ PUT  bb_rsi_overbought: RSI(14)=73.87 > 70 (overbought) AND close crossed above BB(20,2).upper (1.12587 > 1.12584)  @ 1.12587
2026-09-23 20:15:00 UTC GBPUSD_otc   ▲ CALL ema_cross: EMA(9) crossed above EMA(21) (1.14027 > 1.14017)  @ 1.14145
```

> **Read before using**
> - Pocket Option has **no official API**. Everything that talks to it is reverse-engineered and **may violate its Terms of Service**. Your account could be restricted. Use a **demo account** where you can. This tool is read-only and never places trades.
> - **OTC prices are generated by the broker**, not traded on an interbank market (OTC pairs run when the real FX market is closed). Indicators only describe the broker's own synthetic feed. Nothing here shows these signals have any predictive edge. Treat the output as a research tool, not trading advice.
> - Binary/digital options are banned for retail clients or unlicensed in many jurisdictions (EU/EEA, UK, US, and others).

## 1. Data-access approach

| Option | How it works | Reliability | Detection / ban risk | Latency |
|---|---|---|---|---|
| **A. DOM scraping** (Selenium/Playwright reading prices off the page) | Poll the price text or chart in the rendered terminal | **Poor.** Only the charts on screen show prices. Class names are obfuscated and change often. The chart is a `<canvas>`, so there's no text to read. | Medium: a long-running automated browser | **Worst:** polling plus render delay |
| **B. Direct WebSocket client** *(primary, `feed.type: websocket`)* | Connect to the same Socket.IO quote server the terminal uses, and authenticate with your browser's own session frame | **Good while the protocol holds.** One small module to fix when it changes. | Medium-high: a non-browser client (TLS/HTTP fingerprint, no page telemetry) connecting with your session | **Best:** ticks arrive as they're pushed (sub-second) |
| **C. Browser socket tap** *(fallback, `feed.type: browser`)* | Playwright opens the real terminal. The page logs in and runs its own socket. We intercept that socket (`route_web_socket`), read every quote frame, and inject subscription frames for extra pairs. | **Good:** the page handles login, CAPTCHA, auth format and pings, so fewer things can break | **Lowest** of the automated options: real browser, real page, real socket | Same as B plus negligible proxying |

**Choice: B as the default, with C as a drop-in fallback.** Both feed the same protocol decoder, so all downstream code is shared. DOM scraping (A) was rejected. Prices you can't see on screen aren't in the DOM at all, and the rest breaks with every UI tweak.

- Use **B** for the lowest latency and a headless, lightweight process (a server or a Raspberry Pi). You re-copy the session frame when it expires.
- Switch to **C** if B gets rejected (Cloudflare or Origin checks, changed auth format), or if you'd rather just log in normally in a browser window.

What this code deliberately does **not** do: fingerprint spoofing, stealth plugins, CAPTCHA solving, automated credential login, or connection flooding. It uses one connection and paces subscriptions (`subscribe_interval`). It reconnects with exponential backoff and jitter, and it stops outright on an auth rejection instead of retrying.

## 2. Architecture

```
feeds/ (data access)          candles.py        indicators/          signals/            output.py
┌───────────────────────┐    ┌───────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────┐
│ pocket_option.py  (B) │    │ tick →    │    │ registry of  │    │ registry of  │    │ console  │
│ browser.py        (C) ├───►│ OHLC per  ├───►│ rsi, ema,    ├───►│ threshold,   ├───►│ jsonl    │
│ simulated.py (offline)│    │ pair,     │    │ sma, macd,   │    │ crossover,   │    │ (add     │
│   └── protocol.py     │    │ rolling   │    │ bollinger,   │    │ all_of  +    │    │  more)   │
│       (all wire logic)│    │ window    │    │ stochastic   │    │ engine       │    │          │
└───────────────────────┘    └───────────┘    └──────────────┘    └──────────────┘    └──────────┘
                    scanner.py wires the layers together; config.yaml picks the implementations
```

- **Data layer** (`otc_scanner/feeds/`): each feed yields `FeedEvent`s (`ticks`, `history`, `assets`). All Pocket Option wire knowledge lives in `protocol.py`.
- **Indicators** (`otc_scanner/indicators/`): pure pandas, no TA-Lib. Registered by name and instantiated from config.
- **Signals** (`otc_scanner/signals/`): rules read indicator columns and return a direction plus a reason. The engine handles edge detection, warm-up and cooldown.
- **Output** (`otc_scanner/output.py`): anything with `report(signal)` and `status(rows)`.

Signals are evaluated **once per closed candle**, not on every tick, so a signal can't "repaint" inside a bar.

## 4. Authentication and session handling

### Option B: direct WebSocket (`feed.type: websocket`)

The scanner reuses the session your browser already has. It never sees your password.

1. Log in at pocketoption.com in Chrome/Edge/Firefox and open the terminal. Switch to the **demo** account if you're using demo.
2. Open DevTools (F12) → **Network** tab → filter **WS** → reload the page.
3. Click the `socket.io` connection to a `*.po.market` host → **Messages** tab.
4. Find the **sent** (↑) message that starts with `42["auth",`. It looks like
   `42["auth",{"session":"…","isDemo":1,"uid":12345678,"platform":2}]`.
   Right-click → **Copy message**.
5. Export it, keeping the single quotes:
   ```bash
   export PO_SSID='42["auth",{"session":"…","isDemo":1,"uid":12345678,"platform":2}]'
   ```
   Windows PowerShell: `$env:PO_SSID = '42["auth",…]'`
6. Point `feed.websocket.regions` at the right server. `DEMO` is for demo sessions (`isDemo":1`). For a real session use a regional host such as `[EUROPA, SEYCHELLES]`. The Network tab shows which host your browser uses, and you can also paste a full `wss://…` URL there.
7. Run `python -m otc_scanner -c config.yaml`

Session handling:
- The frame is a **bearer credential**. Anyone holding a real-account frame may be able to act as you, so treat it like a password. Never commit it; `config.yaml` only stores the *name* of the env var.
- It stays valid until you log out, change your password, or the platform rotates it. On `NotAuthorized` the scanner exits with code 2 and asks you to re-copy it. It does not keep retrying.
- Network drops and server-side disconnects reconnect automatically (2 s → 2 min exponential backoff with jitter, cycling through the listed regions).

### Option C: browser tap (`feed.type: browser`)

1. Set `feed.type: browser` and `feed.browser.headless: false`.
2. Run the scanner. A Chromium window opens on the terminal. **Log in by hand the first time.** The profile is saved in `~/.otc_scanner/browser-profile`, so later runs stay logged in.
3. Once the page's socket authenticates, the scanner subscribes to the selected pairs through that socket. You can keep the window open or minimized. `headless: true` works after the first login, but a visible browser is less likely to be challenged.
4. `inject_subscriptions: false` gives a fully passive mode. The scanner only reads the pairs you open yourself on screen, so it sends nothing of its own.

If no authenticated socket appears within 5 minutes, the feed stops with an auth error.

## 5. Running

```bash
python -m otc_scanner -c config.yaml                          # as configured
python -m otc_scanner --pairs EURUSD_otc,GBPUSD_otc           # explicit pairs
python -m otc_scanner --timeframe 30 --jsonl signals.jsonl    # 30s candles, also log JSON
python -m otc_scanner --list                                  # available indicator/rule types
python -m otc_scanner -v                                      # debug logging (undecoded frames etc.)
```

**Pair selection.** With `pairs: auto`, the scanner waits for the platform's `updateAssets` list. It keeps active `_otc` symbols that look like currency pairs, optionally filters them by `min_payout`, and sorts them by payout (up to `max_pairs`). If no list arrives, it uses `fallback_pairs`.

**Warm-up.** The default indicator set needs 44 closed candles (MACD 26 + 2×9) before any rule is evaluated. Pocket Option usually sends recent history after a pair is subscribed, and the scanner back-fills from it when it does (logged as `back-filled N candles`). If it doesn't, expect ~45 minutes of warm-up on 1-minute candles. The periodic **Feed status** table shows the ticks/min and warm-up progress for each pair.

## 6. Running on GitHub Actions

`.github/workflows/otc-scanner.yml` (at the repo root) has two jobs:

- **test** runs on every push or PR that touches this folder. It runs ruff and the full test suite, including the Playwright browser test with a real Chromium.
- **scan** runs the scanner itself for a fixed time, then posts the flagged signals as the run's **job summary** (a table) and uploads `signals.jsonl` as an artifact (kept 14 days). You start it from the Actions tab, or on a schedule if you enable one.

### One-time setup

1. Copy your auth frame as in [section 4](#option-b-direct-websocket-feedtype-websocket). A **demo** session is strongly recommended.
2. In the GitHub repo: **Settings → Secrets and variables → Actions → New repository secret**. Name it `PO_SSID` and paste the whole `42["auth",…]` frame as the value.
3. The workflow file has to be on the repo's **default branch** before the "Run workflow" button appears.
4. **If the repo is a fork**, GitHub disables Actions on it by default. Open the **Actions** tab and click *"I understand my workflows, go ahead and enable them"*. Scheduled workflows on forks also stay off until enabled there.

### Running a scan

**Actions → otc-scanner → Run workflow**, then fill in:

| Input | Meaning |
|---|---|
| `minutes` | How long to scan (1–340; GitHub kills any job at 6 h) |
| `feed` | `websocket` (live; needs the secret) or `simulated` (no account; checks the pipeline end to end, with fast simulated time so it fires a lot) |
| `pairs` | `auto` or `EURUSD_otc,GBPUSD_otc,…` |
| `timeframe` | Candle size in seconds |
| `config` | Optional YAML in this folder, e.g. a committed `config.ci.yaml` with your own indicators and rules. Don't use `config.yaml`, which is git-ignored. |

- Signals appear live in the step log **Scan for N minutes**, as well as in the summary and the artifact.
- At the deadline the scanner gets a Ctrl+C and exits cleanly. A rejected session (`NotAuthorized`) or a bad config fails the job instead, so an expired `PO_SSID` shows up as a red run. Update the secret to fix it.
- **Scheduled scans:** uncomment the `schedule:` block in the workflow. The example starts a 5 h 40 min scan every 6 hours, which leaves a small gap between runs. Only one scan runs at a time (`concurrency`).

### Limits and risks specific to GitHub

- **Not a 24/7 service.** Each run is capped at 6 hours, scheduled starts can be delayed by several minutes when GitHub is busy, and every run begins with a fresh warm-up (§5). For continuous scanning, run it on an always-on machine or VPS instead.
- **Datacenter IPs.** Runners connect from Microsoft Azure address ranges. Pocket Option or Cloudflare may block or challenge these more readily than a home connection, so the first live run tells you whether it works. Only `websocket` and `simulated` work on Actions; the browser feed needs a manual first login.
- **Your session runs on GitHub's servers.** The secret is masked in logs and is never passed to workflows triggered by pull requests from forks. Still, anyone with write access to the repo can create a workflow that reads it, so use a demo session. Using the same session in your browser and on Actions at once may log one of them out (unverified).
- **Public repos have public logs.** In a public repository, anyone can read the run logs, summaries and artifacts, which means your signals and the pairs you watch.
- **Actions minutes.** Free for public repos. For private repos, runs count against your plan's monthly minutes, and a 6-hourly schedule uses about 1,400 min/week.

## 7. Changing indicators and signal conditions

Everything is in `config.yaml`; no code changes are needed for the built-ins.

```yaml
indicators:
  - {id: rsi, type: rsi, period: 7}              # column "rsi"
  - {id: st,  type: stochastic, k: 14, d: 3}     # columns "st.k", "st.d"

signals:
  cooldown_bars: 3
  rules:
    - {id: rsi_fast, type: threshold, column: rsi, below: 20, above: 80}
    - {id: stoch_cross, type: crossover, fast: st.k, slow: st.d}
    - {id: hist_flip, type: crossover, fast: macd.hist, slow: 0}          # numeric level
    - {id: trend_only, type: crossover, fast: ema_fast, slow: ema_slow, down: null}  # CALL side only
    - id: confluence                                                      # all must agree on the same bar
      type: all_of
      rules:
        - {type: threshold, column: rsi, below: 30}
        - {type: crossover, fast: close, slow: bb.lower, up: null, down: CALL}
```

- `threshold`: `column` below `below` → `below_direction` (default CALL); above `above` → `above_direction` (default PUT).
- `crossover`: `fast` crosses above `slow` → `up` (default CALL); crosses below → `down` (default PUT). Set either one to `null` to ignore that side.
- `all_of`: fires when every sub-rule gives the same direction on the same bar.
- `mode: edge` (the default) fires only on the bar a condition *becomes* true. `mode: while` fires on every bar it holds, subject to `cooldown_bars`.
- Typos in column names are caught at startup, with the list of available columns.

**New indicator:**

```python
# otc_scanner/indicators/library.py (or any imported module)
@register("atr")
class ATR(Indicator):
    def __init__(self, id, period=14):
        super().__init__(id, period=period)
        self.period = period

    @property
    def min_bars(self):
        return self.period + 1

    def compute(self, df):
        tr = pd.concat(
            [
                df.high - df.low,
                (df.high - df.close.shift()).abs(),
                (df.low - df.close.shift()).abs(),
            ],
            axis=1,
        ).max(axis=1)
        return {"": tr.ewm(alpha=1 / self.period, adjust=False).mean()}
```

**New rule:** subclass `Rule` in `otc_scanner/signals/rules.py`, decorate it with `@register_rule("name")`, and implement `state(row) -> (direction | None, reason)` and `columns()`.

**New output** (Telegram, webhook, sound): add a class with `report(signal)` / `status(rows)` and register it in `output.build_reporters`.

**New data source** (another broker, CSV replay): subclass `feeds.base.PriceFeed` and yield `FeedEvent`s.

## 8. ⚠ Parts that depend on Pocket Option's current front-end/API

These are the places that **will break** when the platform changes. They're kept together so a fix is local. Each is marked `FRAGILE` in the source.

| What | Where | Symptom when it breaks | Where to fix |
|---|---|---|---|
| Quote-server hostnames (`*.po.market`) | `feeds/protocol.py` `REGION_URLS` | DNS/connect errors, endless reconnects | Copy the new `wss://` URL from DevTools into `feed.websocket.regions` (no code change) |
| Origin check (`https://pocketoption.com`) | `protocol.py` `DEFAULT_ORIGIN` | Handshake rejected (HTTP 403) | Update the constant, or switch to the browser feed |
| Engine.IO v4 / Socket.IO framing (`0`, `40`, `2`/`3`, `42[...]`, `451-` binary placeholders) | `protocol.py` `ProtocolDecoder` | No events decoded; `-v` shows "undecodable frame" | Decoder |
| Auth frame format `42["auth",{session,isDemo,uid,platform}]` | `protocol.py` `normalize_auth_frame`; you copy it from DevTools | "no auth response within 20s" or `NotAuthorized` | Re-copy the frame; if its shape changed, use the browser feed |
| Auth result event names (`successauth`, `NotAuthorized`) | `ProtocolDecoder._dispatch` | Hangs at connect, never subscribes | Decoder |
| Subscription frame (`changeSymbol {asset, period}`) | `config.yaml` `feed.subscribe_templates` | Connected but no ticks for your pairs | Edit the template in config: copy what the terminal sends when you switch charts |
| Tick payload `updateStream` → `[[asset, ts, price], ...]` | `protocol.parse_ticks` | Assets arrive, ticks never do | `parse_ticks` |
| Asset list `updateAssets` (positional arrays: symbol at [1], payout at [5], active flag at [14]) | `protocol.parse_assets`, `_guess_active` | Wrong or empty auto-selection | Set explicit `pairs:` as a workaround; fix the indices |
| History payload (`updateHistoryNewFast` / `loadHistoryPeriod`) | `protocol.parse_history` | No back-fill (long warm-up only; not fatal) | `parse_history` |
| Terminal URLs, socket URL pattern | `feeds/browser.py` `TERMINAL_URLS`, `SOCKET_PATTERN` | Browser opens the wrong page / socket not tapped | Constants, or `feed.browser.account: <full URL>` |
| `_otc` symbol suffix | `AssetInfo.is_otc`, `looks_like_fx_pair` | Auto mode selects nothing | `feeds/base.py` |

**Multi-pair streaming (verify on your account).** The web terminal streams the pairs whose charts are open (it supports multi-chart layouts). Whether one socket keeps streaming *every* pair sent via `changeSymbol`, or only the most recent ones, is up to the server and has changed over time. Check the **Feed status** table: a subscribed pair with 0 ticks/min isn't being streamed. If only some pairs stream, you have three options:
1. Copy the frames the terminal sends when you add a chart in a multi-chart layout into `subscribe_templates`. Some versions use an extra `subfor` event, for example `- ["subfor", "{asset}"]`.
2. Lower `max_pairs`.
3. Run a few scanner instances with different `--pairs`.

**Demo vs real quotes.** Demo and real OTC feeds are generally reported to match, but that isn't guaranteed. If you trade on real, check a few prices side by side.

## 9. Tests

```bash
cd examples/pocket_option_otc_scanner
python -m pytest tests -q
```

No network or account is needed:
- The WebSocket feed is tested against a local mock server that speaks the same Engine.IO/Socket.IO sequence: handshake, auth, binary placeholders, asset list, pings, ticks.
- The browser feed is tested by pointing Playwright at a local page that plays the terminal's role. It is skipped if Chromium isn't installed; set `OTC_SCANNER_CHROMIUM=/path/to/chrome` to use an existing binary.
- Indicators are checked against a reference Wilder RSI and structural invariants.
- Signal rules are tested bar by bar, including warm-up and cooldown.

These tests prove the scanner is internally consistent with the protocol **as documented above**. They can't prove Pocket Option still speaks that protocol today. The first live run (with `-v`) is that check.
